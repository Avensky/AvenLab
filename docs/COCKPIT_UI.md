# Cockpit and instrument UI

Open **Cockpit** from the pause menu, the small in-game screen button, or **F4**.
Controller shoulders switch tabs; D-pad navigates buttons; A/Cross activates;
B/Circle closes. Keyboard arrows, Tab, Enter and Space are also supported.
Signal Recon never opens the driving cockpit.

## Controls

- **Drive:** a six-speed H gate with a draggable knob and individual gear buttons,
  an automatic P/R/N/D gate, a separate handbrake lever, TRAC OFF and VSC SPORT.
  Drag the handbrake up/down or tap it to latch/release. Its confirmed lamp shows
  the server's state. Selecting P applies parking through the selector; there is
  no separate Park button. Park/reverse requests are rejected while moving in
  the incompatible direction. The handbrake operates the rear wheels, bypasses
  rear ABS and can hold engine demand at rest without creating backward drive.
- **Lights:** OFF / AUTO / LOW / HIGH on a digital left stalk. Indicator buttons
  sit either side of the small steering-wheel graphic; keyboard/controller
  shortcuts retain the same input owner. AUTO currently provides engine-linked
  running lights; an ambient-light sensor/night cycle is further work.
- **Wipers:** OFF / LOW / MID / HIGH and a 400 ms wash pulse. These modes are
  authoritative state for a vehicle/CAN visual adapter. The cockpit control
  illustrates the sweep; this patch does not add rigs to the vehicle GLBs.
- **Cruise:** ON/OFF, SET, RESUME and CANCEL. SET requires 30 km/h; RESUME requires
  20 km/h and a prior target. This is a simple bounded proportional game assist,
  not a factory cruise controller. Foot/rear brakes, park, engine stop and reverse
  cancel active cruise. Driver throttle can override it temporarily.
- **Radio:** choose a local audio file with SOURCE, then play/pause, mute and
  adjust volume. One browser Audio element remains active when the cockpit is
  closed. Audio bytes stay local; this patch adds no third-party streams.
- **Vehicle:** shortcuts to vehicle selection, missions, settings, debugger and
  resume, presented as head-unit app buttons. The amber clock refreshes twice
  a minute. Hazards use the existing confirmed vehicle mask.

The manual selector is assisted: gear/RPM requests feed the current Rust
powertrain without a clutch or torque-curve overhaul. Sport is the requested
**game** rule: permit a traction-limited launch lasting at least 0.2 s, then
re-arm TCS after it settles for 0.3 s. TRAC OFF and Sport also re-arm above
50 km/h. A factory VSC yaw/brake intervention model is not claimed.

For the factory distinction, the FR-S owner's manual describes automatic TRAC
reactivation above approximately 31 mph/50 km/h when only TRAC was disabled;
VSC SPORT is a separate assist profile. Reference:
https://assets.sia.toyota.com/publications/en/om-s/OM18027U/pdf/OM18027U.pdf

## Exact scales and display power

The outer speed scale is 0–160 MPH: 33 marks, 5 MPH apart, major labels every
20 MPH. The inner scale is 0–260 km/h: 53 marks, 5 km/h apart, major labels
every 20 km/h. Both are generated from one conversion, 1 mile = 1.609344 km.
Consequently 160 MPH ends at 257.49504 km/h, just before the inner 260 mark.
Neither scale crosses the open gap. No labels or ticks are generated by an AI
image renderer. Unit preference changes the numeric display, not the geometry.

Speedometer lamps follow the outer left edge of the adjacent RPM instrument.
The coupe warning SVG has two doors. Fuel and temperature have separate hubs.
The white RPM band extends beyond 0 and 9, and the shallow amber gear/speed
readouts sit side by side below the hub. Confirmed engine stop or unavailable
telemetry blanks them; the confirmed STARTING resource bit makes both pulse
together using CSS opacity. Reduced-motion settings suppress that pulse.
NOS and condition are compact horizontal lines below the instruments.

## Ownership and rates

`inputStore` remains the only requested-input owner. An optional `cockpit_mask`
u32 carries new controls alongside the existing input fields; one existing
socket sender transmits it. Rust owns accepted state and safety checks.
The existing 20 Hz, reference-counted display sampler serves either the gauges
or the open cockpit. Static dial faces are memoized; needles use transforms.
There are no per-gauge animation loops, extra world steps or network writers.

| Request bits | Meaning |
|---|---|
| 0–1 | Light mode |
| 2–3 | Wiper mode |
| 4–5 | Assist mode |
| 6 | Automatic selector |
| 7–10 | Gear: 0=N, 1–6, 7=R, 8=P |
| 11 | Latched parking brake |
| 12 | Momentary washer |
| 13 | Cruise enabled |
| 14–15 | Cruise action: none / set / resume / cancel |
| 16–23 | Request revision, wrapping u8 |
| 24–27 | Changed control group, deduplicated by Rust |

Snapshot `cockpit_mask` uses the same lower state/revision fields; bits 24–27
instead mean cruise active, traction re-armed, parking active and cockpit enabled.
Bits 28–31 report a rejected request. UI shows confirmation after acknowledgement
and cannot label a rejected park/reverse shift as engaged. Rejected gears cannot
silently execute later when an unrelated stalk request arrives.

Setup `hud.cockpit_controls` advertises support. Older servers keep their
existing controls and cannot enable the new cockpit actions. `cluster_fields`
advertises which optional `cluster_mask` lamps are actually supplied. Current
Rust supplies high beam, cruise, parking brake and traction intervention; door,
TPMS, oil/battery faults and EPS await actual models or per-vehicle CAN mappings.
Cranking oil/battery/engine lamps are a bulb-check presentation, not invented
running faults. These application flags are not vehicle-specific CAN IDs.

## Review and checks

Run `npm --prefix frontend run dev`, then open `/previews/cockpit.html` for a
sample-telemetry review. Add `?layout` for the compact driving layout. The
standalone HTML deliverable embeds its code, CSS and icons. The preview's mocked
acknowledgements demonstrate UI states; they are not a physics simulation or
performance benchmark. Source entry: `frontend/previews/cockpit.tsx`.

Passed: 167 frontend tests, 58 Rust tests, ESLint and both production builds.
An actual Rust WebSocket check also passed spawn/calibration, park, assisted
shifting, high beam, wipers, the rear-brake lamp and Sport launch re-arm.
The standalone bundled preview executes its gauge states and every cockpit tab
without script errors in DOM verification.

Automated checks cover equal tick divisions, shared units, dark/cranking/running
states, unchanged static faces under telemetry updates, packed protocol fields,
input ownership, controller menu routing, rear braking, stopped gear constraints,
Sport re-arm and cruise cancellation. Native browser rendering was blocked in
this execution environment (local Chromium socket restriction and the remote
browser could not reach the local server); phone layout/drag rendering remains
for review in a normal browser. No target-device FPS improvement is claimed.
